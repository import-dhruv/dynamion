# Benchmark datasheet

Modelled on the datasheet practice used by Google and DeepMind. The point
is to make a benchmark's composition, intended use, and limitations
legible before anyone quotes a number from it.

---

## 1. Motivation

Single-file algorithmic puzzles do not measure the capability that
matters for long-horizon coding agents: reading an unfamiliar codebase,
making a change across several files, and holding an implementation
consistent across a long session.

`dynamion` measures that instead. Every task spans multiple files,
requires comprehension of seed code that contains deliberate defects, and
is graded by hidden tests that cannot be read during the agent's turn.

## 2. Composition

| | |
|---|---|
| Tasks | 3 |
| Hidden tests | 80 |
| Domains | API design · concurrency · compatibility refactor |
| Languages | Python |
| Agent adapters | 6 (Aider verified end to end) |
| Model tiers actually run | 2 (`qwen2.5-coder:3b`, `qwen2.5-coder:7b`) |
| Human baselines | 0 |
| Average budget | 37 minutes, 45 turns |

**Per task**

| Task | Difficulty | Budget | Graders | Baseline |
|---|---|---|---|---|
| `retry-backoff` | medium | 30 min | 17 tests (0.7) + rubric (0.3) | 4/17 |
| `idempotent-ledger` | hard | 40 min | 16 tests (0.75) + rubric (0.25) | 9/16 |
| `legacy-dateutil` | hard | 40 min | 47 tests (0.75) + rubric (0.25) | 47/47 |

`legacy-dateutil` seeds at 100% by design: its expectations were generated
by executing the seed, so the task scores only whether the agent changes
behaviour it was told to preserve.

## 3. Collection process

Every task is authored clean-room for this project. No upstream
repository is involved. See [../CONTAMINATION.md](../CONTAMINATION.md)
for per-task provenance and what that claim does *not* cover.

Hidden tests are written alongside the task, and where a task's contract
is behavioural compatibility, the expectations are **generated by
executing the seed** rather than transcribed by hand. `legacy-dateutil`
records the seed's SHA-256 in `behaviour-golden.json` so the recording and
the seed cannot drift apart unnoticed.

## 4. Intended use

**Appropriate for**
- Comparing agent configurations on long-horizon engineering
- Studying *how* an agent fails, via stored trajectories
- Regression-testing an agent harness
- Teaching grader design and anti-gaming

**Not appropriate for**
- Ranking general model capability
- Reporting a headline benchmark score
- Drawing conclusions about a model from a single task

## 5. Measurement

Scores are fractional: the fraction of hidden tests passed, combined
across graders by weight. `Resolved` means every hidden test passed.

Grading runs hermetically — `--network none` with the workspace mounted
read-only — so a run cannot depend on anything outside its container.
Every run record states whether it was hermetic, because a non-hermetic
score is a different measurement.

Rubric subscores are computed but **excluded from reported Score**: the
available judge model is too small to rank agents with.

## 6. Known limitations

- **Calibration is failing.** A 7B and a 3B model score identically on the
  only task where both have run (5/17 each). The trajectories separate;
  the score does not. This benchmark cannot currently rank agents.
- **Partial credit floors too low.** Four of seventeen tests pass on the
  untouched `retry-backoff` seed, so an agent that does not regress the
  module starts near baseline.
- **No human baselines.** Difficulty labels are asserted, not measured.
- **Three tasks, one model tier.** No inter-task correlation study.
- **Five of six adapters are unverified.** Written against documented CLI
  surfaces, not executed here.
- **The agent's turn has unrestricted egress.** A local model server must
  be reachable, so an agent could in principle fetch a reference
  implementation.
- **Synthetic tasks are clean but artificial.** Real repositories are
  messier than clean-room constructions.
- **Rubric scoring is noisy** at the available model size.

## 7. Maintenance

- Harness versioned with semver; tasks versioned independently.
- `dynamion validate` enforces: provenance recorded, contamination
  checked, hidden tests present, rubric `k >= 3`, digest-pinned image, no
  hard-coded interpreter, every hidden path resolvable.
- CI asserts hermetic and local grading agree exactly. If the two modes
  diverge, the harness is measuring something inconsistent.
- CI runs monthly to catch base-image drift.
- A regression test pins every grader bug found to date; the README lists
  all twelve.

## 8. Ethics and intended audience

Intended for AI-evaluation researchers and agent developers. Not
suitable as a hiring signal on its own: three tasks from one model tier
with failing calibration cannot support a claim about anyone's ability.
