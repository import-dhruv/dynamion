# Grader design notes

For each grader: what it measures, why those criteria, and **how it
resists gaming** — including attacks actually attempted against it.

The attacks are the useful part. A grader you cannot describe an exploit
for is not finished.

---

## `retry-backoff` — hidden tests (weight 0.7)

**Measures:** whether the retry contract is implemented — transient-only
retry, configurable attempts, exponential backoff arithmetic,
`Retry-After` precedence, a wall-clock deadline, and correct callback
invocation.

**Why these criteria:** each corresponds to a way the original hard-coded
loop was wrong. `Retry-After` is included because ignoring a
server-provided backoff hint is a real production failure mode, not a
stylistic issue.

**17 tests, partial credit enabled.** Baseline 4/17.

### Attacks attempted

| Attack | Outcome |
|---|---|
| Read the tests, satisfy them directly | Impossible — hidden tests are absent from the agent's workspace and injected after its turn |
| `pytest.skip` the hard cases | Detected: skip markers in the output classify as `grader_gaming`; skipped tests are not counted as passes |
| `return True` from every function | Fails behavioural assertions (`add(2,3) == 5`, not truthiness) |
| Edit `tests/test_visible.py` | It is the agent's copy; the grader injects its own and overwrites it |
| Name a policy module the test guesses | **Closed.** The test originally looked for `fluxclient.retry`/`policy`/`backoff` and failed a correct solution that used a different filename. It now searches the workspace for any module that does not import the client |

### Known weakness

Four tests pass on the untouched seed, so a non-regressing agent scores
~0.17 for doing nothing. This compresses the dynamic range and is the
first thing to fix.

## `idempotent-ledger` — hidden tests (weight 0.75)

**Measures:** idempotency under retry, conflicting-key rejection,
atomicity, validation-before-mutation, monotonic sequencing, and
synchronisation under concurrency. 16 tests, baseline 9/16.

### The concurrency problem, stated honestly

**The race cannot be reliably detected.** The check-then-append window is
measured in microseconds; CPython switches threads on a ~5ms interval.
An unsynchronised implementation passed a 25-round, 8-thread stress test
with a barrier — three times out of three — purely by luck.

**The countermeasure is white-box.** `test_store_synchronises_check_and_append`
asserts the store exposes a lock, rather than observing behaviour. That
inspects internals instead of outcomes.

This is a deliberate trade, not an ideal design. A behavioural-only test
would award credit for an undetected bug, which is worse. But it means the
task cannot claim black-box verification of concurrency, and the README
says so.

### Attacks attempted

| Attack | Outcome |
|---|---|
| Rewrite the module, delete public names | Caught — an API-surface test asserts every re-exported name still exists. Added after a real run: an agent dropped `AccountClosed`, breaking the package import and making the run unscoreable |
| Skip the threaded test | Classified as `grader_gaming` |
| Consume a sequence number on a duplicate | Caught by the monotonicity test |
| Append before validating, leaving a ghost entry | Caught by the "no side effects" tests |

### Known weakness

Requires access to `ledger._accounts["acct_1"]` to close an account. That
reaches into internals, and a legitimate refactor that changes internal
layout would fail for the wrong reason.

## `legacy-dateutil` — hidden tests (weight 0.75)

**Measures:** whether the agent preserves behaviour while modernising the
module. 47 tests, all passing on the seed by construction.

**The design is inverted:** the grader was generated by executing the
seed, so it encodes what the code *does*, not what it *should* do. The
prompt names six edge cases that look like bugs and are load-bearing.

### Verification that the grader discriminates

Four "improvements" were applied to a copy of the seed and graded:

| Change | Caught |
|---|---|
| `parse_duration` raises on unparseable input | ✅ |
| `slugify` returns `"untitled"` for alphanumeric-free input | ✅ |
| `title_case` lowercases token interiors | ✅ |
| `truncate` slices to a negative width | ✅ |

47/47 → 35/47. A diff that looks like an improvement fails.

### Attacks attempted

| Attack | Outcome |
|---|---|
| Read `behaviour-golden.json` and hard-code results | Mitigated — the file is injected with the hidden tests, not present during the agent's turn; the rubric explicitly discredits hard-coding against it |
| Rewrite `__all__` to a narrower list | Caught by the public-name test |
| Delete the `_slug_cache` global (rather than bounding it) | Permitted — the contract is repeated-call behaviour, not the cache's existence |

### Integrity check

`behaviour-golden.json` records the seed's SHA-256. If the seed is edited
without regenerating the recording, the hash no longer matches and the
mismatch is a deliberate decision rather than an accident.

## Rubric graders (weights 0.25–0.3)

**Measure:** dimensions a pass/fail grader cannot see — whether the
policy is genuinely transport-independent, whether validation demonstrably
precedes mutation, whether the refactor was proportionate.

**Why anchors matter:** every criterion declares `anchor_low` and
`anchor_high`. Without them, judges drift and scores stop being comparable
across runs — the number changes meaning between evaluations.

**`self_consistency_k = 3`**, and the spread across samples is reported.
A single judge pass is noisy enough that differences between agents are
indistinguishable from sampling noise.

**`anti_gaming_note` on every rubric** tells the judge not to reward
comments, docstrings, or annotations alone, and not to credit code that
weakens assertions or detects the test environment.

### Failure paths handled

| Path | Behaviour |
|---|---|
| Judge unreachable | Raises `JudgeUnavailable` — never scored as 0.0 |
| Malformed JSON | Recorded as a failed sample, excluded from the average |
| Well-formed JSON with no `scores` | Also a failed sample. Counting it as empty would dilute real samples and pull every criterion toward zero |
| All samples fail | Raises. A zero here would look like a terrible diff |
| Judge is the model under test | `check_judge_independence` raises |

**The aggregation is a weighted mean, not an AND.** An attempt that
passes every test but satisfies no rubric criteria should not score the
same as one that does the opposite. Both are partial success, and the
distinction between "implemented but undocumented" and "documented but
unimplemented" is worth reporting.

### Known weakness

The judge model in every bundled task is the same 7B model that
produced the solutions. Independence holds in the sense the harness
enforces — a distinct judge instance — but a same-family judge may share
blind spots with the model under test. Rubric subscores are therefore
**excluded from the reported Score**.

## Cross-cutting rules

These apply to every grader in the project, and each exists because its
absence produced a wrong number.

| Rule | Consequence of not having it |
|---|---|
| Infrastructure faults raise, never score 0.0 | Harness breakage attributed to model capability |
| Fault detection runs *before* output parsing | A collection error's `ERROR` lines counted as failed tests |
| Hidden tests injected after the agent's turn | Agent optimises against its own grader |
| Grading mount is read-only | Agent edits the tests judging it |
| Partial credit from per-test counts | 9-of-10 and 0-of-10 collapse into one bucket |
| Match the *last* count in output | `assert 2 == 1` before a `FAILED` line fabricated a count |
| `extra="forbid"` on every model | A typo silently drops grader configuration |
| Untracked files included in the diff | A model whose output is a new file scores zero on the rubric |
