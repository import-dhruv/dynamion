# Changelog

All notable changes to this project are documented here. The format
follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and the
project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

Task specs are versioned independently with semver, so a task can be
revised without a harness release. See `tasks/<id>/task.yaml`.

## [0.1.0] - 2026-10-14

First public release. The harness, three tasks, and — more usefully — a
record of the grader bugs found while building it.

### Added

**Harness**
- Task specification format with a strict Pydantic model and emitted JSON
  Schema. Unknown fields are rejected rather than ignored, so a typo in a
  task spec fails loudly instead of silently changing a score.
- Two execution environments: `LocalEnvironment` (no isolation) and
  `DockerEnvironment` (hermetic). Every run record states which produced
  it, because the two modes are not comparable.
- Hermetic grading: the test command runs with `--network none` and the
  workspace mounted read-only, so grading cannot reach the network and
  cannot be edited by the thing it is grading.
- Digest-pinned base images, with `dynamion validate` warning when a task
  is not pinned. Tasks may alternatively supply a Dockerfile, built from a
  digest-pinned base.
- Six agent adapters behind one interface: Aider (verified end to end),
  plus Codex, Gemini CLI, Claude Code, Cursor Agent and OpenHands.
  Unverified adapters are marked as such and the leaderboard says so.
- Two grader types: hidden executable tests with fractional partial
  credit, and an LLM rubric judge with anchored criteria, self-consistency
  sampling, and a judge-independence check.
- Failure taxonomy with nine categories. A test asserts every declared
  category is reachable, so the taxonomy cannot silently decay into
  constants nothing produces.
- Setup commands baked into a derived image via `docker commit`, because
  `docker run --rm` discards its filesystem.
- `dynamion validate | list | schema | run | bench`, a dependency-free
  static leaderboard site generator, and per-task run records.

**Tasks** (3, 80 hidden tests)
- `retry-backoff` — configurable retry policy; 17 hidden tests.
- `idempotent-ledger` — idempotency and concurrency in a payment ledger;
  16 hidden tests, including a deterministic structural check because the
  race itself cannot be reliably triggered under CPython.
- `legacy-dateutil` — compatibility refactor where every edge case is a
  recorded behaviour; 47 hidden tests including property-based ones.
  Hidden expectations were generated by executing the seed, and the
  seed's SHA-256 is recorded so the two cannot drift apart unnoticed.

**Infrastructure**
- 84 tests. The isolation suite runs probes inside the container *and* the
  same probes under local mode asserting the opposite, so it cannot pass
  vacuously.
- CI: lint, unit, isolation, and a check that hermetic grading agrees
  exactly with local grading.
- Benchmark workflow that re-runs on adapter or task changes, publishes to
  GitHub Pages, and runs monthly to catch base-image drift.

### Fixed

These were found by executing the harness rather than by reading it. Each
is pinned by a regression test.

- Hidden tests were graded from the wrong path, so every run collected zero
  tests and reported `0.00` — indistinguishable from a total model failure.
- Infrastructure faults were scored as task failures. A broken runner, a
  collection error or a missing plugin now raises instead of returning
  `0.0`. Collection errors in particular were being counted as failed tests.
- An environment fault was classified as `GAVE_UP`, blaming the model for
  harness breakage.
- The pytest summary parser was case-sensitive, reading a fully-failing run
  as `0/0`, and matched the *first* occurrence in the output, so
  `assert 2 == 1` immediately before a `FAILED` line fabricated a count
  and turned a real 4-of-17 run into a reported 4-of-5.
- `classify_failure` called `.get()` on a Pydantic model and crashed on
  every single-grader run.
- Three declared failure modes were unreachable from any code path.
- A malformed judge response was counted as an empty sample, turning a
  flaky judge into a confident low score.
- The task loader validated any YAML or JSON in a task directory, so a
  golden behaviour file broke the entire load.
- `${PYTHON}` resolved to the host interpreter path, which does not exist
  inside a container.
- `pip install` during setup vanished because `docker run --rm` discards
  its filesystem.
